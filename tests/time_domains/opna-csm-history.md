# N6-C bounded native OPNA CSM semantic-history pilot

The default-OFF `NP2_OPNA_CSM_HISTORY` option requires `NP2_OPNA_TIMER_MACHINE_TIME`. It applies only to the experimental Linux SDL2 single-owner native PC-9801-86 (`0x04`) profile. The pre-existing N6-T mode with this option OFF still rejects CSM; default legacy/OFF still invokes the native synchronous CSM implementation. PCM86 must remain quiescent, FMGEN is rejected, and the OPNA ADPCM/Speak Board profiles are outside scope. Existing experimental save/load rejection applies unchanged.

When CSM is enabled, the machine-time owner first computes the exact Timer A expiry count from the N6-T rational phase without mutating the device. It rejects a service target when that count exceeds available history capacity, or if sequence/finalization state is invalid. Before committing, it expands every admitted deadline with checked integer arithmetic into a private local array and advances a **copy** of Timer A/B state. Only after all checks pass does it commit the timer candidate, call real `fmport_a` for each admitted expiry, and append one `CSM_PAIR` after each callback's status/PIC/rearm path. Timer B still has no CSM operation. With CSM disabled, N6-T's analytical O(1)-style Timer A/B service path remains unchanged.

Each private record holds epoch, per-epoch monotonic sequence, exact logical Timer A deadline in nanoseconds, observed service time, Timer A expiry ordinal, `CSM_PAIR` class, and ordered derived subindices 0=key-off and 1=key-on. Service time is diagnostic; it never replaces the logical deadline. `history_finalized_count` seals the published sequence prefix, without claiming that no later guest write can have the same timestamp. Guest I/O still calls machine-time service before applying its register operation. Reset clears the bounded sink and starts a new epoch and sequence; old records can be retained by a test observer only as historical evidence.

The internal accepted frontier is `accepted_frontier_ns` alongside the N6-T anchor. Rejection is an explicit abort with an admission code: 6 incompatible clock/phase profile, 7 capacity, 8 sequence/deadline overflow, 9 incomplete or non-monotonic history. It happens before timer phase, status, PIC, accepted frontier, or finalized records change. The abort cannot be ignored by existing void service callers. Diagnostic rejection fields may update. This is a cold-boot experimental pilot, not a general recovery or product backlog policy.

The buffer is **256 records for host qualification only**. `OPNA_TIMER_MACHINE` is 14,480 bytes with the option ON versus 96 bytes in the N6-T mode, an increase of 14,384 bytes; the record array itself is 14,336 bytes (256 × 56). This number is not a selected product CSM debt limit and has no relationship to the ESP32-P4 queue size. An admitted interval costs O(admitted CSM records); an over-capacity gap is rejected after O(1) expiry counting, without enumerating the gap.

The fixture in `opna_csm_history_binding.py` uses the complete production binary, actual board86/native OPNA/PIC/port binding, and fake machine-time source. GDB holds the CPU while invoking real device service. It checks 2 CPU backends × 2 base clocks; a 100-expiry single service has 100 ordered CSM pairs at exact deadlines, one PIC publication when status first latches, and no CPU ISR acceptance. One large and 100 partitioned services yield identical timer phase, status, PIC state, accepted frontier, sequence, and logical CSM history (service-observed times are correctly diagnostic and may differ). It checks same-time reg27 disable, key and frequency operations, status read, Timer A rewrite, stop/restart, simultaneous A/B, reset, and capacity 255/256. Rejections at 257, first-slot insufficiency, after-finalization insufficiency, sequence corruption/overflow, incompatible clock/phase, corrupt timer state, incomplete prefix, and a huge gap compare complete semantic state before and after.

GDB breakpoints at `fmport_a`, `pic_setirq`, and `set_fmtimeraevent` establish Timer A → status/PIC → rearm callback order before the CSM record appears. Guest `opngen_keyon`/`opngen_setreg` markers at a matching time observe a published CSM record and a cleared service flag. Breakpoints at `sound_sync`, `opngen_csm`, and `opngen_getpcm` assert zero calls **during the machine-time owner service**. They do not prohibit ordinary guest-driven synthesis outside that service or the legacy OFF path. ASan/UBSan and exact W0 replay are independent regressions.

Run the fixture with `python3 tools/test_opna_csm_history.py --binary <fake-time SDL binary> --backend i286 --baseclock 2457600 --output .local/n6-c/fixture` (also `ia32` and `1996800`). The standard output and per-case `report.json` files are machine-readable evidence. This pilot proves bounded legacy-compatibility semantic history, not physical YM2608 timing, ordinary live CSM waveform playback, sample-frontier mapping, FMGEN/PCM86/ADPCM support, Linux realtime service, or P4 deadline compliance. Later N6-W work must supply and independently qualify the sample/generation plan before W0 can establish waveform replay.
